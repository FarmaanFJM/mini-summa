# Windows audit of the Electron desktop shell

Scope: `apps/desktop` main process and preload, `electron-builder.yml`, the installer, the icons, the packaging scripts and the
test seams. The renderer, the core and the Android app are out of scope here (hand-offs are listed at the end).

**Nothing in this document was run on Windows.** The sandbox is Linux (Node 22, Electron 45.1.0). Three kinds of evidence are
kept apart, and every verdict says which one it rests on:

* **Code/config reading**: what the file says (file:line).
* **SIMULATED**: a unit test that injects a Windows platform or Windows-style strings, or forces a failure that Windows
  produces (for example a failed rename). It proves the logic, not Windows.
* **Under Wine 9.0**: the built Windows executable and installer were run under Wine in a throw-away prefix (Wine reports itself
  as Windows 10.0.19043). **Wine is not Windows**: its shell, registry, process tools, PowerShell (a stub) and ConPTY differ, so a
  Wine result is only ever a hint, and every one below is labelled "under Wine".

Verdicts: **OK** (fine as it stands), **FIXED** (changed here, with a regression test), **RISK** (real but not changed, with why),
**CANNOT VERIFY HERE** (needs a Windows PC; the exact check is in the last section).

## Handed over by the Windows core audit (`windows-core.md`, "Open items")

1. **`windowState.ts:77` and `log.ts:44` renamed without a retry.** FIXED (W-14): `fsRetry.ts` is a local helper modelled on the core's
   (EPERM, EBUSY, EACCES only; 15 ms, doubling; 6 tries for the window state, 3 for the log rotation). Tests: `fs-retry.test.ts`
   with injected refusals (SIMULATED), and the log test that fails on the old code.
2. **The shell must `await core.stop()` before the process exits on every quit path, and never call `app.exit` while it is pending.**
   It was wrong: the quit flow gave up on `core.stop()` after 10 s and exited, and `session-end` stopped the core without waiting
   for anything (W-15, W-07). FIXED: the paths are the window close, the tray Quit, a second `app.quit()` (all `quit.request()`),
   Windows shutdown/log-off/installer close (`quit.endSession()`), and a failed start (`failStartup`, which already awaited the
   stop). None of them calls `app.exit` before `core.stop()` has settled; a test reads `index.ts` and requires that the only
   `exit` calls are the quit flow, `failStartup` and the hook guard. The one way out with the stop pending is the person's own
   "Quit now" in a dialog that appears after 20 s, logged as an error. Whether the terminals' process trees really end is
   CANNOT VERIFY HERE (check 17 and 21).
3. **A hook running `Mini-Summa.exe` with `ELECTRON_RUN_AS_NODE=1` must never start a second window or instance.** What the code did
   before the single-instance lock: it took the profile folder, the log and then the lock, i.e. nothing protected it except
   Electron's RunAsNode fuse. With the fuse on (pinned by tests, in the config and in the built executable) Electron never loads
   the application for such a process. FIXED as a second line of defence (W-16): `isHookInvocation(process.argv)` is the first
   statement in `index.ts`. Verified on Linux with the packaged app (hook run and real second launch, see section 2) and under
   Wine; not on Windows (check 5 of the core audit, and check 8 below).

## Must be verified on a real Windows PC

Each check says what to do and what a correct result looks like. Use a standard (non-administrator) account on Windows 10 21H2
or later, or Windows 11, with the installer from `npm run dist:win`.

1. **No administrator prompt.** Run the installer. *Expect:* no UAC prompt; on the install-mode page "Anyone who uses this computer" is greyed out with "(must run as admin)"; files appear in `%LOCALAPPDATA%\Programs\Mini-Summa`.
2. **Shortcut identity.** `Get-StartApps | Where-Object Name -eq 'Mini-Summa'`. *Expect:* one row, `AppID` = `com.minisumma.app`. The Desktop shortcut exists too.
3. **Link before first launch.** Untick "Run Mini-Summa" at the end of the installer, then `Start-Process 'minisumma://settings'`. *Expect:* the app starts on Settings. `reg query HKCU\Software\Classes\minisumma\shell\open\command` shows `"...\Mini-Summa.exe" "%1"`.
4. **Link with the app running.** With the window minimized: `Start-Process 'minisumma://reports'`. *Expect:* the same window is restored and shows Reports; no second window; `%APPDATA%\Mini-Summa\logs\main.log` has `second instance started {"link":true}`.
5. **Uninstall.** Apps & features, Uninstall. *Expect:* one message that names `%APPDATA%\Mini-Summa` and the hooks; afterwards that folder is still there and `reg query HKCU\Software\Classes\minisumma` finds nothing. The quiet uninstall string shows no message.
6. **Old Windows (VM).** On Windows 7/8.1 or Windows 10 before 1809 the installer says it needs Windows 10 version 1809 and installs nothing.
7. **Upgrade while running.** Start two terminals, then run a newer installer. *Expect:* it asks to close Mini-Summa; afterwards `main.log` shows whether the app quit cleanly (`quitting`) or was ended (no such line); after starting the new version the two sessions are "disconnected / resumable" and `Get-Process claude,node,OpenConsole,conhost` shows no leftovers of the old terminals.
8. **Hooks wait (W-11).** In PowerShell: `$env:ELECTRON_RUN_AS_NODE='1'; Measure-Command { & "$env:LOCALAPPDATA\Programs\Mini-Summa\Mini-Summa.exe" -e "setTimeout(()=>{},3000)" }`. *Expect:* about 3 seconds. A few milliseconds means PowerShell does not wait for the program. Then install the hooks, start a Claude session in a project, and confirm that a spool file appears and the session context contains the report protocol. Also time one hook call end to end; it must stay well under the 5-second timeout.
9. **Toasts.** Trigger a permission request with the window minimized. *Expect:* a toast named "Mini-Summa" with the icon; clicking it brings the window to the front on the right project (not only a flashing taskbar button). Repeat with Focus Assist set to "Alarms only": no toast, but the Action Center holds one, and the app still counts it as shown (known limit).
10. **Tray.** *Expect:* an icon (possibly under the "^" overflow), crisp at 100%, 125%, 150% and 200% scaling; left click opens the window; right click shows Open, Quiet mode, Quit; Quit ends the app. Explorer restart (`taskkill /f /im explorer.exe` then start it) brings the icon back.

With a terminal running: the question appears; Cancel keeps everything; "Quit and end terminal" hides the window first, then exits. **Shut down or sign out with a terminal running:** no dialog; after signing in again the session is resumable and `main.log` has `the system is ending the session`.
